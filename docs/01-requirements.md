# TopoSmith 需求规格

> 版本：v0.1（M0） ｜ 需求编号一经分配不再复用；状态：`M0` 本期交付 / `M1`–`M4` 后续 / `✗` 非目标

## 0. 编号约定

- `FR-xx` 功能需求，`NFR-xx` 非功能需求，`NG-xx` 非目标。
- 每条需求都带**验收标准**（可测）。验收标准写不出来，说明需求还没想清楚。

## 1. 绘制与拓扑（FR-01 ~ FR-06）

### FR-01 设备放置 [M0]
从设备面板把设备拖入画布（或点击面板项在视口中心创建）。
**验收**：拖放后设备出现在落点坐标；同一位置重复放置自动偏移避免重叠。

### FR-02 设备移动与选择 [M0]
拖拽移动、单击选中、空白处取消选择、`Delete` 删除选中对象、拖动空白平移画布、滚轮缩放（以指针为锚点）。
**验收**：缩放后指针下的世界坐标保持不变（误差 < 1px）。

### FR-03 端口级连线 [M0]
连线模式下，点选设备 A 的某端口 → 点选设备 B 的某端口 → 生成线缆。
选择线缆后可改类型与长度；不合法组合**拒绝创建并说明原因**。
**验收**：
- RJ45 ↔ RJ45 用 CAT6 可连；
- RJ45 ↔ SFP 被拒绝，提示"电口与光口不能直连，需光模块或介质转换器"；
- WiFi 端口只能与 WiFi 端口建立"无线关联"。

### FR-04 链路派生与协商 [M0]
链路速率 = `min(端口A速率, 端口B速率, 线缆在给定长度下的能力)`；任一端口半双工则链路半双工；
线缆超长或介质不匹配则链路 `down`。
**验收**：CAT6 长 80m 连接两个 10G 电口 → 链路协商为 2.5G 并给出降速提示；
CAT5e 连接两个 10G 电口 → 链路降为 2.5G 并提示线缆上限。

### FR-05 层级容器与小地图 [M1]
房间/楼层/机柜/云等容器节点，支持嵌套与折叠；小地图显示全局视口。
**验收**：1000 节点下小地图滚动帧率 ≥ 50fps。

### FR-06 撤销重做 [M1]
栈式撤销/重做（`Ctrl+Z` / `Ctrl+Shift+Z`），覆盖增删设备/线缆/属性修改。
**验收**：任意 50 步操作序列撤销到底后，场景 JSON 与初始逐字节一致。

## 2. 设备与目录（FR-07 ~ FR-10）

### FR-07 设备类型目录 [M0]
内置目录，按用户给定清单实现：

| 分组 | 类型 |
|---|---|
| 接入与出口 | 光猫（ONT）、OLT 局端、云/互联网出口 |
| 路由交换 | 路由器、交换机（5 口 2.5G / 8 口 1G / 24 口 1G + 2×SFP+） |
| 无线 | 无线 AP |
| 计算机 | 台式机、笔记本、平板、机架式服务器、塔式工作站、迷你主机 |
| 可移动设备 | 手机、平板 |
| 嵌入式设备 | NAS、网络摄像头、网络打印机、IoT 传感器、树莓派 |

**验收**：目录数据与 UI 由同一份 `@toposmith/catalog` 驱动，新增型号不改 UI 代码。

### FR-08 端口目录与模块 [M0]
端口含名称、介质、速率、双工、角色、VLAN 配置；SFP 口记录模块类型（SFP 1G / SFP+ 10G / SFP28 25G）。
**验收**：SFP+ 口与 SFP 口互连时按较低速率协商。

### FR-09 线缆目录 [M0]
CAT5 / CAT5e / CAT6 / CAT6a / OM3 / OM4 / 单模 / DAC / 无线。

**必须实现的真实约束**：
- CAT5：100Mbps / 100m，**不能**跑 2.5G。
- CAT5e：2.5GBASE-T 需两端 NBASE-T 支持；100m 内不支持 10G。
- CAT6：10GBASE-T **仅 55m**（永久链路约 37m），100m 内降至 2.5G。
- CAT6a：10GBASE-T / 100m。**"CAT6e" 非标准名称**，UI 必须标注为俗称并映射到 CAT6a。
- 光纤速率由**光模块**决定，不由线缆决定；多模 OM3/OM4 传输距离受限。
- 铜缆长度 > 100m → 链路直接 down（教学价值最高的判定之一）。

**验收**：目录内含每条线缆的标准名、俗称、速率-长度分档与出处说明；上述五条约束各有一条单元测试。

### FR-10 无线建模 [M1]
SSID / 频段 / 信道 / 加密；终端关联到 AP；协商速率取两端标准较低值；
无线为**共享半双工**介质：N 个客户端同时活跃时单客户端有效吞吐显著下降。
**验收**：同一 AP 下 1 台与 3 台终端下载，吞吐数字随并发下降并在结论中说明原因；
蜂窝路径同一条结论改说"同一小区内的终端数"与"单用户峰值"（预置场景单测）。

## 3. 网络语义（FR-11 ~ FR-16）

### FR-11 VLAN [M0]
Access 口 PVID、Trunk 口允许列表；设备可配置多个 VLAN；广播域按 VLAN 划分。
**验收**：SW1 的 access VLAN 10 接 PC-A、VLAN 20 接 PC-B，二者不同网段 → 不可达，
证据链指出"两端不在同一广播域（VLAN 10 vs VLAN 20）"。

### FR-12 IP 与网段 [M0]
端口/设备级 IP、掩码、网关；支持静态与 DHCP；不同网段需三层转发。
**验收**：同网段无需网关即可互通；跨网段缺网关时给出"无默认网关"结论。

### FR-13 DHCP [M0]
DHCP 服务器：地址池起止、网关、下发 DNS；客户端请求租约；服务器必须与客户端**同一广播域**。
**验收**：
- 池内有空闲地址 → 客户端获得租约，证据链记录"地址 x 由 DHCP 服务器 y 分配"；
- 服务器不在同一广播域 → 客户端无地址，说明"DHCP 广播无法跨越广播域/路由器"。

### FR-14 NAT 与光猫模式 [M0]
设备可开启 NAT（SNAT）；光猫支持**桥接 / 路由**两种模式，决定 NAT 与 DHCP 落在光猫还是下级路由器。
**验收**：家庭场景下私网客户端访问公网 IP 成功并标注 NAT 转换点；
关闭 NAT 后同一推演失败，理由为"私网地址缺少 NAT，公网无回程"。

### FR-15 静态路由 [M0]
按目的网段 + 下一跳配置；转发时最长前缀匹配。
**验收**：同时存在默认路由与明细路由时，明细路由被选中且证据链显示匹配的前缀长度。

### FR-16 PON 接入网 [M1]
OLT–分光器–ONU/光猫；分光比与共享带宽；10G-EPON 上下行能力差异。
**验收**：1:32 分光、10G-EPON 场景下每用户可用带宽约为总带宽/在线用户数，并写入结论说明。

## 4. 四类诊断（核心能力，FR-17 ~ FR-21）

> 统一的输出契约见 `07-diagnostics.md`。所有诊断**必须**返回证据链，而不只是布尔值。

### FR-17 可达性测量 [M0]
选源设备、选目标 IP，输出 通/不通 + 阻断原因链。
**验收**：至少覆盖 12 种失败原因（见 `07-diagnostics.md` 原因码表），每种都有独立测试用例。

### FR-18 数据包链路 [M0]
输出逐跳列表：跳序、设备、入接口、出接口、链路协商速率与介质、下一跳 IP、NAT 转换点。
**验收**：家庭场景「笔记本 → 公网」链路完整，含 NAT 转换点与 PON 上行。

### FR-19 通讯速度 [M0]
输出：瓶颈链路（哪一跳、多少速率）、逐跳速率、单向时延、RTT、单流有效吞吐、
传输 1 GiB 的估算耗时、以及所有降速提示。
**验收**：路径中存在 1G 与 10G 链路时，瓶颈必须指向 1G 那一跳；
无线路径额外给出共享介质说明与并发衰减。

### FR-20 DNS 解析路径 [M0]
输出：客户端 → 本地 DNS →（转发）→ 权威的完整链路，标注每一步是缓存命中 / 静态记录 /
转发，以及 TTL 与失败点。
**验收**：首次查询走完整链路并写缓存；同一会话内第二次相同查询命中缓存并标注 TTL；
域名不存在时返回 NXDOMAIN 且展示已走到的最后一跳。

### FR-21 设备视角批量可达性 [M1]
从一台设备出发，对一组目标 IP 批量测量，输出矩阵视图。
**验收**：20 个目标批量推演 < 200ms。

## 5. 数据与交互（FR-22 ~ FR-26）

### FR-22 场景导入导出 [M0]
导出为 JSON（含 schemaVersion）；导入时校验；版本不匹配时给出明确错误。
**验收**：导出→导入→再导出，两次 JSON 逐字节一致。

### FR-23 预置场景模板 [M0]
至少一个开箱可用的家庭场景：光猫（路由模式）→ 交换机 → 有线终端，AP → 无线终端，OLT/云在上行。
**验收**：打开应用即可直接运行四类诊断并看到有意义的结果。

### FR-24 URL 分享 [M1]
拓扑压缩进 URL fragment，打开即还原。
**验收**：100 节点场景 URL 长度 < 8KB。

### FR-25 本地持久化 [M0]
自动保存到 `localStorage`，刷新不丢。
**验收**：刷新页面后拓扑、选中态与视口恢复。

### FR-26 配置导出为真实设备命令 [M4]
把建模结果导出为 Cisco / 华为语法配置片段，供真实设备部署参考。
**验收**：导出文本可被人工核对；不含厂商商标素材。

## 5.1 画布效率与可视化（FR-27 ~ FR-30，第二轮迭代）

### FR-27 多选与批量操作 [M0]
Shift 点选切换、空白处拖动**框选**（相交即选中）、`Ctrl/Cmd+A` 全选；对多选设备提供
批量移动、批量删除、**六向对齐**（左/右/水平居中/顶/底/垂直居中）与**两轴等距分布**。
**验收**：
- Shift 点选 3 台后，检查器出现多选面板并显示 `已选 3 台设备`；
- 执行左对齐后三台的 x 坐标**完全一致**；
- 等距分布后首尾不动、相邻间隙相等；
- 框选覆盖全画布时选中全部 10 台设备（冒烟脚本实测）。

### FR-28 对齐吸附与引导线 [M0]
拖动设备时同时参与两类吸附：**网格吸附**（默认 8 世界单位）与**节点对齐吸附**
（与其他节点的左/中/右、上/中/下参考线对齐）；命中时绘制贯穿画布的虚线引导线；
按住 `Alt` 临时关闭吸附。
**验收**：把设备拖到"卡片左边缘距邻居左边缘 1 单位"处（目标 381，而 380 不是 8 的倍数），
最终必须精确落在 **380** —— 该结果只能来自节点对齐而非网格吸附（冒烟脚本实测）。

### FR-29 链路流向与速率动画 [M0]
运行「可达性 / 数据包链路 / 通讯速度」后，在画布上沿**实际路径**播放流向动画：
- 粒子沿折线运动，**速度按链路速率对数映射**（100M ≈ 55、1G ≈ 110、10G ≈ 165 单位/秒），
  快链路肉眼可见更快；
- 沿线绘制方向箭头，明确流向；
- 数据包链路模式**逐跳停顿**并显示当前跳序与跳数徽标；
- 诊断失败时粒子**停在阻断点**并显示红色脉冲与"数据到此中断"；
- 提供暂停 / 重放 / 0.5×–4× 倍速控制；
- 路径必须包含二层实际穿过的链路（见 D-23），不允许"越过中间交换机画直线"；
- 系统设置 `prefers-reduced-motion: reduce` 时**不自动播放**，只保留手动播放。

**验收**：预置场景中源为笔记本（无线 1201 Mbps）时，动画提示的最慢一跳必须是
**1 Gbps**（交换机→光猫那段网线），而不是无线协商速率（冒烟脚本实测）。

### FR-30 设备与端口图标 [M0]
设备卡片、设备面板、端口行与对齐工具条统一使用 **Lucide**（ISC 许可，商用免费）图标；
画布用 `Path2D` 描边、面板用 SVG，两者**共用同一份图标数据**，避免两套图标漂移。
**验收**：页面渲染 58 个 SVG 元素；画布上的设备图标与面板中同一设备的图标同源同形。

### FR-31 撤销 / 重做 [M0]
`Ctrl/Cmd+Z` 撤销、`Ctrl+Shift+Z` / `Ctrl+Y` 重做，工具栏按钮同步灰显并提供操作名提示。
**验收**：
- 删除设备 → 撤销恢复 → 重做再删除 → 再撤销恢复，四步状态全部正确（冒烟脚本实测）；
- 一次拖动只产生**一条**历史（连续 60 帧的拖动不能变成 60 次撤销）；
- 连续输入设备名在 1.2 秒窗口内合并为一条历史（不能退化成按字符撤销）；
- 导入/恢复预置/清空场景会重置历史。

### FR-32 端口图元与端口详情 [M0]
设备卡片底部常驻**端口条带**：每个端口按介质画成对应形状
（RJ45 网口的梯形卡扣、SFP 光笼、PON 带芯光口、无线天线），端口名在图元下方；
已连接端口按**链路速率着色**、未连接为灰色、链路不可用为红色。
点击端口图元进入**端口详情面板**（速率/双工/角色/VLAN，以及连接情况与断开操作）。
**验收**：
- 26 口交换机自动换行两行且全部落在卡片内，同行图元互不重叠（单测）；
- 命中测试取容差内最近端口，相邻端口不会互相抢点击（单测）；
- 浏览器中点击交换机 GE3 后，检查器显示「书房交换机 · GE3」（冒烟实测）。

### FR-33 端口到端口连线 [M0]
连线不再从设备中心到设备中心，而是**从端口图元出发、以电缆状曲线接入对端端口图元**；
端口与卡片底边之间绘制"引出线"，让"电缆插在哪个口上"一眼可见。
**验收**：
- 曲线起点 x 等于源端口图元中心 x、y 等于卡片底边；终点同理（单测）；
- 曲线必须离开卡片下垂，而不是穿过卡片中心（单测）；
- 同一设备的不同端口接入点不同（单测）——这是"端口到端口"而非"设备到设备"的判据。

### FR-34 链路速率配色 [M0]
连线标签的**文字颜色与边框颜色**、以及连线本体与已连接端口图元，
统一按链路速率着色：**带宽越高越绿，越低越红**。
映射锚点：**1 Gbps = 红（色相 0）**、**10 Gbps = 绿（色相 145）**，
两者之间按**对数刻度**均匀分配（速率感知是倍率关系）；超出该范围用**亮度**继续区分
（100M 比 1G 更暗，100G 比 10G 更亮）。画布右上角提供图例。
**验收**：
- 色相随速率单调不减，且 2.5G / 5G 落在区间内部而非端点（单测）；
- 1G 标签为红、2.5G 为琥珀、10G 为绿（截图核对）；
- 图例刻度按对数位置排布，覆盖 100M / 1G / 2.5G / 10G / 100G。

### FR-35 Ctrl 多选与诊断面板联动 [M0]
`Ctrl`（macOS 为 `Cmd`）与 `Shift` 点击都用于追加/取消选中设备，且**保持点击顺序**；
当选中 ≥2 台设备时，把**最后两台**自动填入连通性诊断面板：**倒数第二台为源、最后一台为目标**
（即"先选中的是源设备"），同时清空上一次的推演结果并在面板上标注来源。
**验收**：
- Ctrl 依次点 A、B、C → `selection.devices` 顺序为 `[A,B,C]`，诊断源 = **B**、目标 = **C**（单测）；
- 再 Ctrl 点一次 A 取消它 → 只剩 B，来源标记被撤掉（单测）；
- 目标设备没有 IP 时不覆盖原目标地址，并提示需要补地址（单测）；
- 浏览器中面板出现"已由选中设备填入：A → B（先选中的为源）"（冒烟实测）。

### FR-36 机柜容器 [M0]
新增**机柜**容器设备：可设定高度（1–24U）；机架式设备（机架服务器 / 交换机 / OLT）可放入机柜，
画面表现为**机柜正面视图**（U 位编号 + 导轨 + 槽位，默认 24U、可调 8–48U）；
**比例遵循真实 19″ 机架**（设备宽 482.6 mm ÷ 1U 高 44.45 mm ≈ 10.86，见 FR-41）；
标题栏右侧有**翻转图标按钮**
（Lucide `rotate-3d`，不写文字，与「正面/背面」文本之间保留固定间距）在正/背面之间切换，
悬浮时高亮并在下方显示「翻转到背面/正面」提示；
**鼠标悬浮时机柜半透明**，可直接看到另一面的端口；**两面都可以有端口，具体视设备而定**
（例：服务器网卡全在背面、接入交换机端口全在正面、24 口交换机另有 1 个背面管理口、OLT 的 PON 在正面而上联光口在背面）。
**验收**：
- 端口带 `side`（front/rear），上架设备只显示与当前观察面一致的端口（单测 + 正/背面对照截图）；
- 上架写入 `mount{rackId,startU}` 并把卡片移动到对应 U 位；多台设备依次占用不同 U 位（单测）；
- 机柜移动时柜内设备一起移动、相对位置不变（单测）；
- 把设备拖出机柜自动下架；调低高度后放不下的设备自动下架（单测）；

### FR-38 设备端口可增删 [M0]

### FR-39 设备可占多个 U [M0]
**一个设备不等于 1U**：机架式设备的高度（**默认 4U = 一张标准卡片**，可调 4–24U）在
**设备卡片**（右侧设备检查器的「机柜安装」区块）中配置，卡片在画布上按该高度绘制
（8U 卡片高度 = 8×U 高），端口面板随卡片一起变高；
上架时按所占 U 数寻找**连续空位**，跨占的 U 格在机柜里显示为一段高亮带；
调高已上架设备的 U 数会重新找位置，机柜装不下时自动下架并提示。
**验收**：
- `cardHeightForUnits(4)` 恰好等于标准卡片高度、更大的 U 数让卡片变高；
  `rackUnitsOf` 缺省 4 且钳制 4–24（单测）；
- 默认 4U：两台设备依次占用第 1–4U 与第 5–8U；OLT 默认 8U，后续设备从**第 9U** 开始（单测）；
- 把已上架的 4U 设备改成 8U → 重新落到装得下的位置（单测）；
- 8U 机柜里把设备改成 12U → 自动下架并提示（单测）；
- 多 U 设备的端口接入点下移到更高卡片的底部（单测）。

### FR-40 端口画在面板上 + 设备级翻转 [M0]
端口不再挤在卡片底边，而是**绘制在设备面板上**（卡片头部之下、底边之上的面板区，

（与机柜同款、同样带「正面/背面」标识与悬浮提示），点击即在正/背面端口之间切换。
上架设备的观察面**跟随机柜**（翻转机柜即翻转柜内所有设备），因此不再单独显示设备翻转按钮。
**验收**：
- 端口图元落在面板区内、电缆接入点仍在卡片底边（单测）；
- 4U 卡片的面板能放下一行带名称的端口；27 口设备自动换行（单测）；

### FR-41 机柜与设备比例遵循真实 19″ 机架 [M0]
机柜不做"看起来差不多"的宽度，而是**由真实比例反推**：
`1U 高 = 23`（= 标准卡片的 1/4）→ **设备面板宽 = 23 × (482.6/44.45) ≈ 250**（19 英寸设备）→
**机柜外宽 = 250 × 1.24 ≈ 310**（真实机柜外宽约为设备宽的 1.24 倍，多出的是两侧导轨）。
**上架设备的卡片宽度跟随机柜**：上架后卡片宽度 = 设备面板宽度 250（正好铺满两导轨之间），
未上架时用标准卡片宽度 152 —— 与"卡片高度跟随机柜 U 数"是同一套思路。
**验收**：
- `RACK_EQUIPMENT_W / RACK_UNIT_H ≈ 10.86`、`RACK_W / RACK_EQUIPMENT_W ≈ 1.24`、
  且 `设备宽 + 两侧导轨 = 机柜外宽`（单测）；
- 上架设备卡片宽度 = `RACK_EQUIPMENT_W`、未上架 = `NODE_W`；U 位内容区宽度就是设备宽度（单测）；
- 4U 上架卡片宽高比落在真实 4U 设备（≈2.7）附近（单测）；
- 同一台 27 口交换机在上架后（卡片变宽）占用行数不增加，且图元不越界（单测 + 截图核对）。

### FR-42 数字输入的提交语义（输入期间不钳制）[M0]
所有数字输入框**在输入期间只保留草稿文本**（不解析、不钳制），
在**失焦或回车**时才提交：合法输入按 `min`/`max` 钳制，非法/空输入还原原值，`Esc` 放弃本次编辑。
`min`/`max` 同时交给浏览器，因此上下小三角的可达范围与真实范围一致；
数值范围写在字段提示里（如「8–48U」/「4–24U」），且提示文案与 `min`/`max` 取自同一组常量。
**验收**：
- 逐键输入 `42`：第一键后输入框显示 `4`（不被抬到下限）、第二键后显示 `42`、失焦后取值为 **42**（冒烟实测）；
- 输入 `99` 失焦后钳制到上限 48（冒烟实测）；
- 机柜高度字段 `min=8 / max=48`、设备 U 高字段 `min=4 / max=24`（冒烟实测属性值）；
- 空串与非法字符提交时保持原值不清空（单测）；
- 小数、负数按范围处理（单测）。

### FR-46 连线速率标签可拖拽定位 [M0]

### FR-48 有背板端口的设备悬浮半透明（透视）[M0]
**凡是有背板端口（`port.side === 'rear'`）的设备**，鼠标悬浮在它上面时卡片变半透明，
并把它**另一面的端口图元以幽灵形式画出来** —— 与机柜悬浮是同一套"透视"约定
（`HOVER_FADE = 0.42`，机柜与设备共用一个常量）。只有前面板端口的设备**不参与**淡出：
没有背面可看，淡出只会让画面抖动。上架设备同样适用（悬浮柜内设备淡出的是这台设备本身）。
指针**离开画布**时清掉全部悬浮态（半透明、端口高亮、标签高亮），否则会一直挂着。
**验收**：
- 有背板端口设备：悬浮后卡片像素朝"设备背后的东西"靠拢 —— 三点测量
  `ratio = dist(悬浮后, 移开后) / dist(不悬浮, 移开后) = 0.70 < 0.75`（像素断言）；
- 端口带出现背面端口的幽灵图元（该区域像素变化，7–8 灰度差）；
- 只有前面板端口的设备：悬浮前后像素**完全不变**（ratio = 1.000）；
- 指针移出画布后像素回到悬浮前的值（差 < 2）；
- 上架设备悬浮：配色条显著淡出 + 端口带出现背面幽灵端口；
- **命中测试里容器让位于具体设备**：指针落在柜内设备上时命中该设备，
  且与 id 字典序无关（单测：机柜 id 排在设备前/后两种情形结果一致）。
- 边界（有意为之）：幽灵端口是**提示**而不是靶子 —— 要连背面的端口，
  请先翻转设备（未上架）或翻转机柜（已上架）；画布上的端口点击仍然只认当前观察面。

### FR-49 卡片宽度可调（非机柜内设备）[M0]
未上架的设备卡片宽度可调（`MIN_CARD_W 120`–`MAX_CARD_W 420`）：**拖卡片右边缘**，或在检查器里

**上架设备不可调**（宽度由机柜的 19″ 面板决定，允许改会出现"卡片比导轨还宽"的自相矛盾状态）；
机柜本身也不可调。宽度是**纯展示属性**，不参与推演，但会影响端口图元的排布（宽了自动少换行）。
**验收**：
- 拖右边缘后 `cardWidth` 真的落盘（实测 152 → 208），撤销一步回到 152（端到端）；
- 检查器里的数值与画布一致（端到端）；

### FR-50 拖拽设备时连线有平面物理摆动 [M0]
每条连线记一个**摆动偏移**（世界单位），偏移加在两个控制点上：**两端接入点不动、
线身甩出去**，所以看起来是"电缆被拽着甩"而不是"整根线平移"。
受力模型是**端点位移给线身一个冲量 + 弹簧把线身拉回原位 + 阻尼收敛**：
稳速拖动有稳定滞后，快甩得到一次冲量然后**来回摆几下再停**。
短连线幅度自动减小（`span/160` 缩放，下限 0.25）；输入速度与线身速度都有硬上限，
所以"瞬移"（撤销、批量重排）只会换来一次有界的甩动。
**验收**：
- 慢拖时偏移明显非零（实测峰值 7.5 世界单位）；
- **快甩时摆动随速度放大**（实测峰值 61 世界单位，触及上限 60）—— "拖得越快甩得越远"；
- 松手后**换向一次再静止**：偏移之和符号翻转 ≥1，且 ~19 帧（<0.5s）内收敛到静止（端到端）；
- 静止时不产生任何偏移，且**不做常驻 rAF**（没有物理要算就停掉循环）（单测 + 实现约定）；
- 帧率无关：60fps 与 120fps 跑同样时长结果接近（单测）；`dt` 异常（切标签页回来）不炸（单测）；
- 从静止被唤醒的那一帧**折减**速度而不是丢弃（否则"整段甩动落在两帧之间"时等于没甩）（端到端）；
- 超快甩动与瞬移的幅度有界、非数字输入不污染状态（单测）。

### FR-51 适应视图：完整装入且不留过多空白 [M0]
"适应"把**设备卡片 ∪ 连线的折线**（电缆会垂到卡片下方）算进内容范围，
用**真实画布尺寸**计算缩放并把内容居中；**留白是屏幕像素**（28px），与缩放无关。
缩放上限 2（内容很小时不无限放大），下限只做数值兜底（0.02）——
**"装得下"优先于"别缩太小"**：一百台设备的拓扑就该缩到 0.05 才看得全。
**验收**：
- 预置场景：内容完整在画布内，被约束轴留白 56px（= 2×28）（端到端）；
- 摊开到 10 台设备（跨度 ≈9000×1500）：缩放 0.122，仍完整在画布内、留白 56px（端到端）；
- 单台设备：完整在画布内且缩放顶到上限 2（留白不可避免，但不该"缩在中间一小块"）（端到端）；
- 画布尺寸真的参与计算：2000 宽的视口与 700 宽的视口得到不同缩放（单测）；
- 留白可调、内容位置不影响"装得下"、退化输入不产生 NaN（单测）。

### FR-52 观察面用按钮颜色与提示表达，不再常驻文字 [M0]
设备卡片与机柜标题栏上的「正面/背面」文字**移除**：当前观察面改为用**翻转按钮的边框与图标颜色**
表达（正面 = 亮青 `#7dd3fc`，背面 = 琥珀 `#fbbf24`，就是原来那行文字的颜色），

### FR-55 场景内容的建模约束（写场景时会踩到的三条）[M0]
写预置场景时踩到并固定的三条引擎语义（不是场景的疏忽，是 M0 的已知简化）：
1. **VLAN 要两端都对上**：`portCarriesVlan` 看的是"这个端口承载哪个 VLAN"，
   广播域跨线缆时会检查**对端端口**；真实网络只给交换机口打标，终端网卡不打标；
2. **家用网关的 LAN 桥只在 VLAN 1 生效**（`LAN_BRIDGE_VLAN`，D-17）：
   所以带无线的段必须待在 VLAN 1，否则 AP 的无线口并不进有线段；
3. **终端型设备缺省是 DHCP 客户端，租约会覆盖 `l3.interfaces`**：
   要固定地址必须显式退出 DHCP；且静态地址必须挂在**有连线的端口**上，否则永远 ARP 不到。
**验收**：三条都在预置场景的注释里写明，并各有单测/端到端佐证。

### FR-66 链路聚合（LACP）建模：并联线缆不再一律当成环路 [M0]
"C 两根线接到同一对交换机"在真实网络里是两件完全不同的事：**做了聚合**就是带宽叠加的
冗余上行，**没做聚合**就是二层环路 + 广播风暴。M0 之前两种情况都无法表达，于是走严环路检测后
会把合法的双上行设计一律判成故障。现在 `Cable` 增加 `bonded?: boolean`：

- 语义是「与对端之间的聚合组」，**不带组 id**：同一对设备之间所有 `bonded` 线缆即同一组，
  多条时在推演中收缩为**一条逻辑链路**（真机上的 LACP / 静态聚合）；
- 置位方式只有一处 UI：选中线缆 → 检查器「链路聚合（LACP）」勾选框，
  一次勾选**改的是同对端的所有线缆**（一根线谈不上聚合，也不该留下"孤零零的成员"），
  且只记一条历史，一次撤销回到原样；
- 只在确实存在第二根并联线缆时可勾（否则禁用并说明"聚合至少要两根成员"）；
- 导入校验兜底：无线关联不能聚合、成员数为 1 的聚合组报错。

**验收**：
- 并联两根、都没标 `bonded` → 判出一处二层环路；两根都标上 → 环路归零（引擎单测）；
- 三根并联、只标了两根 → 第三根照样报环，环路径里聚合组显示为「（聚合 2 根）」（引擎单测）；
- 检查器勾选后环路数 3 → 2、同对端两根一起被标记、Ctrl+Z 一步回到 3（端到端，
  `.verify/loop-preset.mjs`）；store 单测另验"一次撤销"与"不误伤别的链路"；
- 预置 IDC 场景的 24 柜 × 3 机房双上行标为聚合后，**800 台设备里零环路告警**（单测 + 端到端）；
- 聚合**不改变可达性**：聚合并联线之后原先能通的仍然通（store 单测）。

### FR-67 二层环路检测与「广播风暴」告警 [M0]
新增 `l2/loop.ts`：按 VLAN 建端口组图（节点 = 设备内端口组，边 = 线缆 + 设备内部转发），
用 Tarjan 找非桥边定位所有卷进环路的线缆，再为每条非桥边求一条**首尾闭合的代表环路径**。
判定规则、星形中心与上限等工程细节见 `docs/05-engine.md` §2「二层环路」。

结论以三种方式落地（都不改变"拓扑上可达"这个事实本身）：

1. **诊断证据链**：源（或目的）所在广播域有环时，`ping`/`trace`/`bandwidth` 输出两步
   `warn` —— `L2_LOOP`（点名环路径、VLAN 与波及设备数）与 `BROADCAST_STORM`
   （以太网帧没有 TTL → 广播帧沿环无限循环 → 环内最慢一段先被打满 → MAC flapping →
   整个 VLAN 受影响），并在结论措辞里披露"不建模风暴动力学与 STP 端口状态机"；
2. **结论文本**：`ping` 的 summary 追加环路提示；`bandwidth` 的 summary 明确"这两个数字是按
   没有风暴算出来的估计值，真机上不成立"（否则用户会把 950 Mbps 当真）；
3. **链路与设备检查器**：每条卷进环路的线缆挂 `L2_LOOP` 告警（画布上同时出现琥珀告警点），
   设备的检查器给出"所在广播域有 N 处二层环路"+ 环路径。

**验收**：
- 引擎单测 14 项：**该报的报**（并联双线 / 自环跳线 / 无线中继混合环 / 聚合后仍有第三根）
  与**不该报的绝不报**（树形拓扑、主机双归、跨 VLAN 并联、聚合双上行、介质不匹配的 down 链路、
  路由模式网关不同 VLAN 的 LAN 口），外加环路径闭合性、告警级别、确定性、上限截断
  （33 处环 → 报 32 条但**全部 66 根线缆**都被标记）；
- 端到端：环路预置场景里跑可达性诊断，证据链出现「检测到二层环路」与「广播风暴风险」两步
  且级别都是 `warn`；服务器段（另一 VLAN）诊断里一个字都不提环路；IDC 场景零环路；
- 性能：810 台设备的 IDC 场景里环路扫描约 **8 ms**（载入整套 65 → 75 ms），
  预置场景性能预算（负载 < 400 ms、拖动中位帧 < 40 ms）继续满足（端到端）。

### FR-68 预置场景「网络环路与广播风暴」[M0]
新增第 7 套预置场景（17 台设备 / 20 条链路）：办公段（VLAN 1）里**三处典型成环**，
服务器段（VLAN 20）是一棵干净的树，用作对照组：

1. 一楼↔二楼接入交换机之间的**两根"冗余"网线**（GE23/GE24），没做聚合也没有 STP；
2. 二楼接入交换机上一根 1 m 跳线**两端插在自己身上**（GE7–GE8）；
3. 二楼 AP 既用网线接回交换机、又**无线中继**到办公 AP —— 环路不必全是有线。

**验收**：
- 三处环全部检出、全部在 VLAN 1，环路径首尾闭合且能对上端口名（单测）；
- 波及范围 = VLAN 1 内 12 台设备，服务器段完全不受影响（单测：办公 ping 服务器报环路、
  服务器 ping 服务器不报）；
- **三处都能修好**（预置场景也是排查教材，同 FR-54 的做法）：把冗余两根标成聚合 → 少一处环；
  拆掉冗余两根里的一根 + 拔掉自环跳线 + 撤掉无线中继 → 环路归零，且办公段与服务器段仍然互通；
- 场景通过导入校验；弹窗里可选、载入后画布构图完整装入（实测适应视图 0.70），
  端到端脚本逐项验过（`.verify/loop-preset.mjs`）。

### FR-69 两侧侧栏可拖拽调宽 [M0]
左（设备目录 + 节点树）与右（检查器 + 诊断）**两侧**侧栏的宽度都可拖：拖侧栏内侧的
竖直分隔条（`role="separator"` / `aria-orientation="vertical"`，指针捕获），

宽度是**使用偏好**：与拓扑分开落盘（`toposmith.ui.layout.v1`），刷新后保持，不进撤销栈。

并且当窗口变窄时上限跟着收（`窗口宽 − 另一侧宽度 − 画布下限 360px`）——
**拖侧栏不能把画布挤没**，窗口恢复后宽度回到用户设定值。

**验收**：**左栏的分隔条必须紧贴左栏右边缘**（`gapFromSidebar = 0`、在画布之前、不在窗口右半侧）——

### FR-70 侧栏页面：左栏页签切换、右栏堆叠面板、页面可拖到另一侧 [M0]

侧栏由若干**页面**组成，每页是一整块内容；**两侧的排布方式故意不同**：

- **左栏用页签**：设备目录与节点树**共享同一块空间**，一次显示一页，点页签切换

- **页面可以在两侧之间来回搬**，且**内容跟着页面走**：页面 id → 内容的映射只有一份

- 布局（页面顺序、选中页签、折叠、权重、两侧宽度）与拓扑**分开落盘**
  （`toposmith.ui.layout.v1`），刷新后保持；页面被搬走后选中的页签会重新落定。

**验收**：默认停在设备目录、页签 `aria-selected=true`、节点树那页**不在 DOM 里**（一次只渲染一页）；
点「节点树」后整页显示（页高 > 侧栏高度 × 0.7，实测 10 行）且目录页从 DOM 消失；
页签换位后顺序变化并**刷新后保持**；把节点树页签拖到右栏 → 右栏出现 3 块面板、2 条分隔条，
**内容跟着搬过去**（面板里有过滤框与节点列表，不是诊断面板）；再拖回左栏变回页签；
折叠诊断面板后它只剩 38px、检查器立刻变高（实测 132 → 更大的比例）；
16 项布局单测（含"选中的页签必须真的在左栏里"）+ 9 项 store 单测覆盖读写与容错。

### FR-72 无线覆盖建模：全向 / 定向、半径以米计 [M0]
无线设备（AP、家用网关的无线侧、蜂窝基站）可以有**覆盖区域**：`RadioCoverage`
（`shape: 'omni' | 'sector'`、`radiusM`、定向时的 `angleDeg` / `azimuthDeg`、`enabled`）。
半径用**米**，画布按固定比例 `1 米 = 20 世界单位`（D-56）绘制，两者只差一个常数，
因此"画出来的圈"就是"判定用的圈"。

- 全向 = 以设备卡片中心为圆心的圆；定向 = 以中心为顶点、朝向 `azimuthDeg`
  （0° = 画布右方，顺时针为正）、开合 `angleDeg` 的扇形；
- 半径范围 1–5000 m（超过 5000 会夹取），开合角 5–360°；
- 只有 `mode === 'ap'` 的一端有覆盖；覆盖是**每台设备各自的**数据（模板实例化时深拷贝，
  改一台 AP 不会动到另一台）；
- 关掉（`enabled: false`）表示"不判定也不绘制"，给只关心逻辑链路的场景留出口。

**验收**：半径按 20 u/m 换算的边界单测（40 m = 800 世界单位：799 在内、801 在外）；
定向扇形的正/反两侧单测；覆盖手柄的命中与拖动换算 14 项单测；半径在面板里填写后立即生效。

### FR-73 覆盖判定：出圈的关联不成立 [M0]
关联是否成立由**覆盖几何**判定（D-57），与"用户画了哪根无线链路"是两件事：

- 客户端必须落在提供方的覆盖内（两端都是提供方时落在任一方内即可）；
- 出圈 → `WIRELESS_OUT_OF_COVERAGE`（error）→ 链路 down、速率 0，
  证据链里写明"相距多少米、覆盖半径多少、还差约几米"，
  定向还要写明"是方向不满足"；
- 关掉覆盖（或整条关联两端都没有覆盖信息）→ 不做判定，退回旧行为。

**验收**：引擎 9 项覆盖单测（圈内/圈外/边界/定向/关闭/蜂窝回落/PLMN/制式）；
端到端把半径从 30 m 拖到 8 m → 两条关联当场断开、原因码正确、撤销一次回到 20 m、
再撤一次回到 30 m（一次拖动只记一条历史）。

### FR-74 无线关联不再画线，改由覆盖圈 + 信号波 + 标签表达 [M0]
画出覆盖之后，无线关联在画布上**不再绘制线体**：

- 只要任一端有覆盖信息，这条关联就由"覆盖圈（谁覆盖谁）+ 信号波动画（此刻是通的）+
  标签铭牌（协商速率 / 失败原因）"三者表达；线体的命中测试一并关掉
  （不画的线不该能点到，否则空白处点击会选中看不见的链路）；
- 信号波画在**独立覆盖层**上（D-59）：以**无线设备卡片中心为原点**、沿**直线**射向接收设备，
  表现为**若干条平行的弧线**依次推进（形态与参数见 FR-84），
  15 fps、按需启停、尊重 `prefers-reduced-motion`（开启时只画静态图）；
- 断开的关联保留一个淡红点与标签上的**短原因**（超出覆盖 / SSID 不一致 / 制式不匹配 /
  PLMN 不一致），不写笼统的"不可用"；
- 两端都没有覆盖信息的旧场景**退回虚线**，行为与上一版一致。

**验收**：差分验证"真的没有画线"——关掉覆盖后同一条关联重新出现描边
（细线像素采样 0 → 38，`.verify/coverage.mjs`）；覆盖层在无机房场景
（机房机柜预置）像素为 0、在有无线关联的场景非 0 且两帧内容不同（确实在动）；
810 台设备的 IDC 场景加载与拖动帧时与上一版一致。

### FR-75 覆盖的交互编辑：拖手柄与面板填数 [M0]
两条路径改同一份数据：

- **画布**：圈边（全向整圈、定向的弧边）拖半径；扇形的两条半径边拖朝向；
  角平分线 0.5 半径处是朝向手柄，弧边两端是开合角手柄。命中优先级
  "显式手柄 > 隐形边缘"，且**指针下有设备卡片时边缘不参与**（想拖卡片就别改覆盖）；
  拖动整段只记一条历史；
- **检查器**：新增「覆盖区域」面板 —— 启用勾选框、形状（全向/定向）、半径（米）、
  定向时的开合角与朝向（0° 指向右、顺时针为正），并回显"圈内 N 台设备 · 无线关联 M 条
  （其中 K 条不可用）"与每条不可用的原因。

**验收**：端到端拖半径手柄 → 半径精确变为目标值（20 m / 8 m）；
拖扇形半径手柄 → 50 → 70 m；拖朝向手柄 → 朝向从 90° 转到 270° 且原本"在半径内、
方向不对"的那台终端**当场恢复**（这条同时证明了朝向手柄与覆盖判定的正确性）；
面板切形状/填角度/填朝向立即生效；键盘撤销在输入框里不生效（保留原生撤销）。

### FR-76 蜂窝设备：4G / 5G 基站与 5G CPE [M0]
新增三种设备模板（详见 D-58 与 `docs/03-catalog.md`）：

- **4G 基站（LTE）** / **5G 基站（NR）**：`base-station` kind，回传 SFP+ / 电口 + 管理口 + 无线口，
  默认全向 150 m（城区微站口径），二层行为与 AP 一致（空口桥接到回传）；
- **5G CPE**：`router`，无线口做上行（关联基站）、LAN 口带内网，即"无线宽带 FWA"；
- 无线制式扩展 `lte` / `nr`；速率 LTE 150 Mbps、NR 1000 Mbps（单用户峰值）；
  网络标识用 PLMN；世代不同按低的回落并给出 `warn`；
  WiFi 终端与蜂窝基站直接互接 → `RADIO_TECH_MISMATCH`（error）；
- 一台设备一个覆盖区域：三扇区站用三台基站（分别转 0°/120°/240°）表达。

**验收**：引擎蜂窝单测（在圈内协商速率、回落、PLMN 不一致、制式不匹配、
蜂窝终端经基站 DHCP 出网）；预置场景 8 项单测；
端到端在真实界面上核对三台基站的形状/朝向与三类失败链路的标签。

### FR-77 预置场景「蜂窝网络（4G/5G + 定向覆盖）」[M0]
第 8 套预置场景（16 台设备 / 15 条链路）：云 → 核心路由器（NAT/DHCP/DNS）→ 回传汇聚 →
回传接入 → 三台基站（1 台 4G 全向 40 m、2 台 5G 定向：一台朝右 120°、一台朝下 90°），
终端按覆盖判定关联，另有一台 5G CPE 用无线口做上行、LAN 口带一台台式机。

**三处刻意留的问题**（预置场景也是排查教材，同 FR-54 / FR-68）：
一台手机落在 5G 扇区的**背面**（距离够近、方向不对）、一台平板跑出了所有覆盖圈、
一台只有 WiFi 的笔记本接在 4G 基站上（制式不匹配）—— 三条都可修：
拖回扇区 / 拖回圈内 / 换成蜂窝终端。

**验收**：结构（3 台基站、LTE 1 + NR 2、两个扇区朝向 0°/90°）、
速率（4G 150 / 5G 1000）、三处失败的原因码各不相同、
"把平板拖回扇区就恢复"、CPE 的 WAN 地址与 LAN 侧台式机能出公网、共享介质并发数 ——
全部由单测覆盖；场景通过导入校验，端到端在弹窗里可选、载入后画布完整。

### FR-78 无线口与制式的一致性：缺配置要说清"缺在谁身上" [M0]
一次真实用户提问暴露的三处不一致（"无线端口缺少制式配置"到底该改哪里）：

1. **面板不能假装有默认值**。制式未设置时，下拉必须如实显示「未设置（无法协商速率）」——
   此前它用 `?? '802.11ax'` 顶上，于是"面板显示 WiFi 6、引擎报文说缺少制式"，
   用户看到的是一个自相矛盾的界面；
2. **报文必须点名设备与端口**。`WIFI_SHARED_MEDIUM` 的文案改成
   "没有设置无线制式：书房台式机（WLAN1）"，两端都缺时说"两端都…"，
   并说明链路仍算通、只是速率未知，以及去哪里改（面板的「无线」一节）；
3. **手动加的无线口自带一份最小配置**。「有射频但没有任何制式」在真机上不存在，
   而目录模板的无线口都自带制式 —— 只有"手动加口"这条路径能造出它。
   现在加无线口会同时补上 `{ 客户端, 802.11ax, 5GHz }`（SSID 留空，不猜），
   并在 toast 里说明补了什么、还差什么；
4. 顺带补上**缺 SSID** 的提醒：WiFi 客户端没填 SSID 时给 `SSID_MISSING`（warn）——
   速率照给，但明确写"真机上它不会关联到任何 AP"。蜂窝终端不适用（它靠 PLMN）。

**验收**：引擎单测 4 项（点名设备与端口 / 两端都缺 / 缺 SSID 提醒 / 蜂窝终端不误报）；
store 单测 2 项（加无线口自动补配置且不动已有配置）；端到端
`.verify/missing-standard.mjs` 12 项断言：加口后自动协商 1201 Mbps 并提示填 SSID、
清掉制式后面板显示「未设置」且报文点名、填回制式立刻恢复、补齐 SSID 后告警清零。

### FR-79 从端口直接拖拽到端口完成连线 [M0]
连线原本只有"点两次"一条路（连线模式下点起点端口、再点终点端口）。新增**拖拽**：

- 在任何模式下**按住一个端口图元拖动**，越过 4 px 阈值后即拉起一条橡皮筋（起点端口 → 指针，
  末端一个圆点），松手落在另一个端口上就完成连线；落空处＝取消（拖拽是一次完整手势，
  松手必须给出结果，而不是留下"半连线"状态）；
- 拖动中指针下方的端口照旧高亮（与命中测试同源），因此"能不能松手"看着就清楚；
- **单击端口仍然只是"选中端口"**：不越过阈值不会进入连线状态，旧习惯不受影响；
- 连线模式下按下端口仍走原来的"设起点 / 完成连线"语义（点两次完全不变）；
- 完成连线时统一调用 `store.clickPort`，因此**拖拽与点两次共用同一套校验与提示**：
  介质不匹配、电口已占线、同设备两口、无线多关联等规则不可能出现两套。

**验收**：端到端 `.verify/interactions.mjs`：拖拽建线（端点正确、草稿清空）、拖到空处不建线、
同设备两口被拒且提示与点两次一致、已占用电口被拒、单击只选端口且不进连线状态、
点两次仍然可用。

### FR-80 右键上下文菜单与「测量无线信号」 [M0]
画布上**右键**弹出上下文菜单（`role="menu"`，`↑↓` 导航、`Enter` 执行、`Esc` / 点空白关闭、
在别处再右键则菜单跟过去）。菜单只放**真的能执行**的命令（D-53 的同一条原则）：

| 命令 | 行为 |
|---|---|
| 测量此点的无线信号 | 在指针位置弹出测量面板，并在画布上留下一个青色准星标出"量的是这里" |
| 适应视图 | 与工具栏「适应视图」同一个动作 |

**测量面板**（`measureWireless`，引擎纯函数）显示这一点能收到的无线信号：

- **每条信号**：提供方（设备名 + 类型）、制式、频段、信道、SSID 或 PLMN、与测量点的距离、
  覆盖半径、覆盖余量、几何质量档位（极佳 / 良好 / 一般 / 较弱 + 质量条）、
  **自由空间估算的接收电平（dBm）**、标称速率与估算速率、以及"同一提供方已连 N 台"；
- **信道情况**：按（频段，信道）聚合的表格 —— 频点（MHz）、信号数、干扰标记
  （`同频干扰` / `邻频重叠` / `无重叠`）。2.4 GHz 按"信道号相差 < 5 即重叠"判定
  （只有 1/6/11 互不重叠），5G/6G 与蜂窝只有同频才算；
- **口径与简化披露**（照抄内核给出的 notes）：能收到 = 落在启用的覆盖内；
  电平是**自由空间**估算、不含墙体与天线方向图（室内实测通常低 10–20 dB）；
  估算速率 = 标称 × 半双工共享效率 × 质量系数 ÷ 并发数，是量级参考而非 MCS 表；
  蜂窝没有信道号，按制式代表频点（LTE 1.8 GHz / NR 3.5 GHz）估算。

**右键的语义变化**：右键原本是三种平移方式之一（D-21），现在让位给上下文菜单；
平移仍有**中键**与 **Space + 左键**两条路（`.verify/interactions.mjs` 断言右键不再改变视口）。

**验收**：引擎 15 项单测（口径 / 数字 / 信道聚合 / 确定性）；
端到端 12 项断言：菜单弹出与两项命令、右键不平移、`Esc` 关闭、面板列出 AP 与信道、
面板上的 dBm 与 `measureAt()` 引擎结果一致、圈外明确报"收不到"、准星画在画布上。

### FR-84 信号波形态：卡片中心出发的直线平行弧线 [M0]
无线关联的"此刻是通的"用信号波表达，形态按用户给定重做：

- **原点**＝无线设备（提供方）的**卡片中心**，终点＝接收设备的**卡片中心**（不是端口位置）；
- **走直线**：不再沿连线的贝塞尔曲线绕行，两点之间直接连一条直线；
- **形态**＝若干条**平行的弧线**（同一曲率半径，因此彼此平行）依次从发射端推进到接收端；
  每条弧的弧心退回一个半径，于是弧顶正好落在那条直线上、朝接收端鼓起 ——
  弧线有"波前"的指向性，一眼能看出从谁发向谁；
- **密度不随距离变化**：波前个数 = `round(直线长度 / 70 px)`，限制在 3–8 条；
  相位回绕时整串波无缝衔接；
- **两端淡出、中段最实**（`sin(πt)` 包络）：发射端与接收端附近都不刺眼，
  弧线也不会盖住两端的卡片；
- **半径随缩放按 √zoom 收缩**（26 px → 下限 9 px）：缩到 13% 时仍然看得见，
  但不会在放大时显得比卡片还大。

**验收**：8 项单测（波前数量随距离变化并被夹在 3–8、平行＝半径全等、弧顶在直线上、
朝接收端鼓起、竖直方向同样成立、半径随缩放的上下限、起止角对称、
几何以两张卡片中心为首尾）；端到端 12 项断言（`signalWaveFronts` 钩子：原点＝提供方卡片中心、
终点＝对端卡片中心、弧线半径全等、每条弧顶都在 from→to 线段上、相位推进使波前移动、
覆盖层真的有像素且在动、缩放到 40% 后半径收缩但仍平行）。

### FR-81 应用内拦截浏览器原生右键菜单（输入框除外）[M0]
TopoSmith 是一个**应用**而不是网页：右键在画布上是上下文菜单，在两侧栏、工具栏、
我们自己的菜单与面板上也没有什么原生菜单该做的事 —— 留着它只会盖住应用界面。
因此在应用根节点统一 `preventDefault`，**输入框 / 文本域 / 下拉框 / 可编辑区除外**：
那里原生的右键菜单是"粘贴 IP / SSID"的入口，拦掉等于砍掉一个高频操作。

一个实测出来的漏洞值得记下来：**我们自己的上下文菜单上没有拦**。
`contextmenu` 会在**松手时**派发，而此时菜单已经挂载、指针正落在菜单上，
于是"在菜单上右键"会漏出浏览器原生菜单（用户第一句反馈就是"没有拦截浏览器的右键"）。
现在菜单卡片自己也拦，端到端逐处断言 `defaultPrevented`。

**验收**：`.verify/interactions.mjs` 记录三处（画布、我们自己的菜单、右侧栏）的
`contextmenu` 事件并断言全部 `defaultPrevented === true`；输入类控件保持 `false`。

### FR-82 无线网络标识从"能收到的信号"里选 [M0]
设备面板的「无线」一节：SSID（WiFi）与 PLMN（蜂窝）除了手动输入，还能从
**这台设备位置上能收到的**网络标识里直接挑：

- 候选来自引擎的无线测量（`measureWireless` 在设备卡片中心测一次），因此"能收到的"
  与诊断判定的"覆盖内 / 覆盖外"**完全同源**；自己不算候选；
- 同一个 SSID 由多台 AP 广播时只列一条（留质量最好的那台作代表）；
- 选项里带**质量档位、频段、信道、来源设备**（PLMN 还带 dBm），选 SSID 时**频段一起同步**——
  客户端频段决定速率表那一档，不同步就会出现"配了同一个 SSID 却按另一个频段的速率协商"；
- 一个都收不到时如实说明，并提示"检查是否落在提供方的覆盖范围内（可以拖覆盖圈，
  或把设备拖近一点）"，而不是给一个空列表让人猜。

**验收**：端到端：选择器列出可收到的 SSID 且带质量与信道；把 SSID 改成错的 → 链路报
`SSID_MISMATCH`；用选择器挑回 → SSID 与频段都被同步、链路恢复。

### FR-83 信号测量面板里的信道重叠图 [M0]
测量面板的「信道情况」在表格之上多一张频谱图（纯 SVG，布局计算在 `lib/channel-chart.ts`，
有单测）：

- **2.4 GHz**：一个信道占约 22 MHz ＝ **5 个信道号宽**，画成**频谱穹顶曲线**，
  被两条以上曲线覆盖的区间用琥珀色底衬高亮 —— 1 与 3 严重重叠、1 与 6 刚好相接、
  1 与 11 完全分开，看图即得，并附一句"工程上只用 1/6/11"；
- **5 GHz / 6 GHz**：信道正交，画成**离散占用条**（横轴按实际用到的信道收紧），
  同一信道 ≥2 台时标 `×N` 并转红，说明"正交信道不会重叠，但同频会互相等待"；
- **蜂窝**：没有信道号，只报信号数与制式；
- 重叠判定与引擎的信道聚合（FR-80）一致：2.4G 差 < 5 即重叠，其余只有同频才算。

**验收**：9 项单测（1/3 重叠 3 格、1/6 相接不重叠、1/11 分开、同频整段、连续区间合并、
2.4G 双穹顶、5G 正交占用条、同信道标红、蜂窝单独成图）；端到端断言 SVG 按频段渲染、
2.4G 场景画出 2 条曲线 + 1 段重叠、正交频段画占用条且报"无重叠"。
