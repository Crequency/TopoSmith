# TopoSmith 产品概览

> 版本：v0.1（M0） ｜ 最后更新：2026-09-17

## 1. 一句话定位

**TopoSmith（拓扑匠）是一个跑在浏览器里的网络拓扑绘制与连通性推演器**：用户手动画出网络结构，
标注每一根线缆的类型、长度与两端端口的速率/介质，然后让工具回答四个问题——
**通不通、走哪条路、能跑多快、域名怎么解析到那里**，并给出**为什么**。

中文名 **拓扑匠**，强调"手工精细标注"这一产品气质：端口速率、电口/光口、线缆类别这些
别人当装饰的字段，在 TopoSmith 里是计算的一等输入。

## 2. 核心判断：这是推演器，不是仿真器

这是本项目最重要的一个架构决策，写在最前面，避免后续被"能不能加个逐包回放"带偏。

用户要的六项"模拟"能力，逐条拆开看，**没有一项需要逐包实时仿真**：

| 需求 | 计算本质 | 是否需要事件队列 |
|---|---|---|
| 两点通讯速度 | 路径 → 瓶颈链路速率 + 累加时延 | 否 |
| 设备可达性测量 | 逐跳转发判定（L2 域 + L3 最长前缀匹配） | 否 |
| 数据包链路 | 单条路径的逐跳展开（traceroute 语义） | 否 |
| DNS 解析路径 | 请求链遍历 + 缓存/TTL 判定 | 否 |
| VLAN / 网段 | 广播域划分与成员集运算 | 否 |
| 端口/线缆/速率 | 约束求解（min 协商） | 否 |

于是：

- **收益**：一次完整推演是**毫秒级图计算**，纯前端、零后端、可静态托管；1000+ 节点不掉帧；
  结果**确定可复现**（同输入同输出），这是自动判分与回归测试的前提。
- **代价**（明确接受）：不做逐包回放、不做 PCAP 级还原、不跑真实协议报文、不提供设备 CLI
  （用户通过图形面板配置设备）。

算力对比说明取舍的分量：1 Gbps ≈ 1.5 Mpps，10 条千兆链路跑 600 秒虚拟时间约 9×10⁹ 个事件，
单线程引擎能力在 10⁶–10⁷ 事件/秒量级——**差两到三个数量级**。相反，500 节点 OSPF 收敛的
控制平面事件量在 10⁵–10⁶，浏览器里跑得飞起。所以"要不要做逐包仿真"的答案不是"难"，
而是**"物理上不成立，且产品也不需要"**。

术语约定：

- **推演（deduction）**：从拓扑与配置出发，用确定性算法求出路径、可达性、速率、解析链。本项目内核做的事。
- **仿真（simulation）**：按时间推进逐个处理报文事件。本项目**不做**，出现在 issue 里一律按非目标处理。
- **世界（World）**：一次推演的完整输入与派生结果（拓扑 + 链路协商 + 地址分配）。

## 3. 目标用户与场景

| 用户 | 场景 | 产品价值 |
|---|---|---|
| 网络初学者 / 学生 | 家庭网络为何断网、VLAN 为什么隔离不通 | 证据链直接指出阻断点，替代"靠猜" |
| 网络工程师 | 方案评审：这条链路够不够跑万兆、改一条链路的影响 | 秒级推演 + 瓶颈定位 |
| 教学 / 培训机构 | 出题与自动判分 | 确定性推演可作为判分依据 |
| 售前 / 方案 | 给客户画一张能自解释的拓扑 | 拓扑即文档，可导出分享 |

## 4. 产品能力全景（M0 目标态）

**绘制**：设备目录拖放、端口级连线、线缆类型与长度标注、撤销重做、缩放平移、小地图、导入导出。

**建模**：
- 设备：光猫、路由器、交换机、计算机（台式/笔记本/平板/机架服务器/塔式工作站/迷你主机）、
  可移动设备（手机/平板）、嵌入式设备（NAS/摄像头/打印机/IoT/树莓派），
  另有无线 AP、**4G/5G 蜂窝基站**、**5G CPE**、OLT 局端、云出口。
- 端口：RJ45（100M/1G/2.5G/5G/10G BASE-T）、SFP/SFP+/SFP28（1G/10G/25G）、PON（EPON/GPON/10G-EPON）、WiFi。
- 线缆：CAT5 / CAT5e / CAT6 / CAT6a（俗称 CAT6e）/ OM3·OM4 多模 / 单模（LC-LC）/ DAC / 无线关联。
- 无线：SSID / 频段 / 802.11 标准 / 信道；**覆盖区域**（全向圆或定向扇形，半径以米计，
  画布按 1 米 = 20 世界单位绘制）；蜂窝的制式（LTE / NR）与 PLMN。
- 网络：IP、掩码、网关、VLAN（access/trunk）、DHCP 池、静态路由、NAT、光猫桥接/路由模式。
- 服务：DHCP 服务器、DNS 服务器（静态记录 + 转发 + 缓存）。

**四类诊断**（产品的核心，全部输出**证据链**）：
1. **可达性**：选源、选目标 → 通 / 不通 + 阻断原因（哪台设备、哪个端口、哪条 VLAN）。
2. **数据包链路**：逐跳展开进出接口、协商速率、介质类型、NAT 转换点。
3. **通讯速度**：瓶颈链路、逐跳时延、RTT、单流有效吞吐、大文件传输耗时。
4. **DNS 解析路径**：客户端 → 本地 DNS → 转发 → 权威，标注缓存命中/TTL/失败点。

## 5. 明确非目标（Non-Goals）

以下内容**不在**产品范围内，且不属于"以后再说"，而是设计上就不做：

1. 逐包实时仿真、PCAP 级流量还原、拥塞窗口演化。
2. 运行真实网络操作系统镜像（Cisco IOS / FRR / vSRX 等），不涉及镜像分发与授权问题。
3. 设备 CLI 配置界面（不模拟 `configure terminal` 交互；配置通过图形面板与 JSON 完成）。
4. 网络安全攻防仿真（不模拟漏洞利用、不模拟攻击流量）。
5. 真实协议报文交互（不实现 BGP 状态机与真实邻居建立）。
6. 需要后端才能完成的能力（M0–M2 保持零后端；协作编辑需后端时另行立项）。

## 6. 差异化：为什么不用 Packet Tracer / GNS3

| 维度 | TopoSmith | Packet Tracer | GNS3 / EVE-NG / CML |
|---|---|---|---|
| 部署 | 浏览器，零安装，可静态托管 | 桌面客户端 | 需本地虚拟化环境 |
| 物理层精细度 | **线缆类别 + 长度 + 端口介质/速率参与计算** | 弱（连线基本无物理约束） | 真实，但配置成本高 |
| 结果解释 | **证据链：不通的每一层原因** | 只给结果 | 真机行为，但不解释"为什么" |
| 确定性 | 同输入同输出，可判分/可回归 | 部分 | 依赖真机时序，不确定 |
| 真实协议保真 | 不追求 | 中等 | 最高 |

**TopoSmith 不争"最真"，争"最会解释"**。用户拿不到答案时最痛的不是"不通"，而是
"我知道不通，但不知道卡在哪一层"。

## 7. 术语表

| 术语 | 含义 |
|---|---|
| 端口（Port） | 设备上的物理/逻辑接口，有介质、速率、双工、VLAN 角色 |
| 线缆（Cable） | 连接两个端口的物理介质，有类别与长度 |
| 链路（Link） | **派生结果**：线缆 + 两端端口协商后的实际速率/双工/可用性。用户不直接编辑 |
| 广播域（Broadcast Domain） | 某 VLAN 下能二层互通的一组端口，被三层设备终结 |
| 证据链（Evidence Chain） | 推演过程中按顺序记录的判定步骤，每条含结论、原因码与人类可读说明 |
| 地址（Address） | 设备的有效 IP：静态配置或 DHCP 租约推导得出 |
